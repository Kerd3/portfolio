01 / OVERVIEW

Plans, cases, reports and automation.

This repository groups practical QA exercises into manual testing for SauceDemo, API testing against Reqres, and Playwright UI automation. The work covers test planning, positive and negative cases, expected-versus-actual results, and a small set of automated browser scenarios.

02 / MANUAL TESTING / SAUCEDEMO

Scope and defects in shopping flows.

The manual test plan includes login, product listing, add/remove from cart, and checkout. The saved test-case document contains examples for valid login, invalid login, empty credentials, adding an item, and removing an item. Bug reports document an unclear validation message for empty login credentials and a cart counter that did not update after adding an item.

Open manual testing artifacts

03 / API TESTING / REQRES

API checks, negative cases included.

The API exercise uses Reqres endpoints for listing users, retrieving a single user, and logging in. The cases check expected HTTP status codes, response content, and a failed login request with a missing password. A separate API bug report records a generic validation response as an issue to investigate.

Open API testing artifacts

04 / UI AUTOMATION / PLAYWRIGHT

Automate selected browser flows with JavaScript.

The repository contains two Playwright spec files with eight test cases across login and cart behavior: valid login, invalid login, empty username, empty password, protected inventory access, adding one item, adding multiple items, and logging out. It uses Playwright, JavaScript, and Node.js. The README instructs running the project with npx playwright test.

Open Playwright project

05 / SCOPE & NEXT STEPS

Coverage stated without inflation.

The repository currently contains eight Playwright test cases in two spec files. This page does not claim a test pass rate or CI result because no execution result is included in the inspected source. The next practical improvements are to complete the currently empty Playwright config, replace the placeholder npm test script, populate the empty Postman collection file, and publish test execution evidence.
